9월 중순 논의(평판 관리 점검, 사내 AI 포탈 연동, Notifuse·시중 서비스 비교, 배포 중 작업 처리)에서
나온 항목. 우선순위 표기는 위와 같다.

### 발송 평판·발신자

- [ ] 🔴 **스팸 신고율 별도 정지 기준** — 지금은 스팸 신고를 반송과 함께 세어 10% 에서 정지한다.
      SES 정지선은 컴플레인율 0.5% 라 훨씬 낮다. 최근 7일 컴플레인율 0.1~0.3% 에서 워크스페이스 정지
      (`SendingSuspensionService` 에 한 축 추가).
- [ ] 🔴 **운영 DNS 의 DMARC 확인** — SPF·DKIM 은 기록이 있으나 DMARC 기록이 없다. Gmail 은 하루
      5천 통 이상 발신자에게 요구한다(설정 작업, 코드 없음).
- [ ] 🔵 **워크스페이스별 발신 도메인 인증** — 계열사가 자기 도메인(`news@계열사.com`)으로 보내는 기능.
      SES 도메인 등록 → DKIM 레코드 안내 → 검증된 도메인만 발신 허용. 지금의 `APP_SENDER_DOMAIN` 을
      워크스페이스 단위로 넓히는 작업. 스티비는 고객 도메인 발신 + Gmail·네이버 주소 자동 변환을 제공한다.
- [ ] 🟡 **(광고) 표기 자동화** — 정보통신망법상 광고 메일 제목 표기. 캠페인 옵션 또는 워크스페이스
      기본값. 요건은 법무 확인 후.
- [ ] 🟡 **수신 동의 증빙 강화** — 지금은 유입 경로(직접 입력·CSV)와 시각만 남긴다. 이중 동의
      (double opt-in) 구독 흐름 검토.

### 사내 AI 포탈 연동 (MCP — [mcp-integration-design.md](mcp-integration-design.md))

- [ ] 🔴 **수신거부 푸터·오픈 픽셀을 `</body>` 앞에 삽입** — 지금은 본문 끝에 이어 붙여, 완성형 HTML
      문서면 `</html>` 뒤에 붙는다(수신거부 링크가 버려질 수 있음). 콘솔 HTML 에디터에도 해당.
- [ ] 🔴 **이메일 본문 검증** — 저장 시 지원하지 않는 변수(`{{고객명}}` 등 — 빈칸 또는 그대로 노출),
      크기 상한(Gmail 약 102KB 초과 시 잘림), `<script>`·`<iframe>`·`<form>` 거부. 경고를 돌려준다.
- [ ] 🟡 **행위자 헤더** — 포탈 사용자 이메일을 받아(워크스페이스 멤버일 때만) 테스트 발송 수신자·
      감사 로그·캠페인 등록자로 쓴다. API 키 하나를 여러 사람이 공유하는 구조라서 필요.
- [ ] 🟡 **이미지 업로드 도구** — 포탈이 이미지를 직접 호스팅하지 않을 때만.
- [ ] 🟡 `create_email` 도구 시그니처를 서비스에 맞춤 — `name` 필수, `text` 없음.
- [ ] 🔵 **콘솔 내장 AI (MCP 이후)** — 사용자가 자기 모델을 등록하고 콘솔에서 제목·본문 초안을 만든다.
      우리는 입력·출력 형식과 검증만 책임. 설계는 [ai-compose-design.md](ai-compose-design.md).

### 마케팅 기능 격차 (Notifuse 비교)

- [ ] 🔵 **자동화 흐름(여정)** — 가입 환영, 일정 기간 후 후속 메일 같은 연쇄 발송. 가장 큰 공백.
- [ ] 🔵 **속성·이벤트 기반 세그먼트** — 지금은 오픈·클릭률 하한뿐. 연락처 속성 조건, 구매·방문 같은
      사용자 정의 이벤트, AND/OR 조합.
- [ ] 🟡 **템플릿 조건문·반복문** — 지금은 `{{변수}}` 단순 치환.
- [ ] 🟡 **UTM 자동 부착** — 캠페인 링크에 `utm_source`·`utm_medium`·`utm_campaign`.
- [ ] 🟡 **워크스페이스 시간대 기준 예약**
- [ ] 🟡 **발송 이벤트 웹훅(밖으로)** — 고객 시스템에 발송·오픈·클릭·반송을 알린다.
- [ ] 🟡 **역할 세분화** — 지금은 ADMIN/OPERATOR 2종.

### 운영·배포

- [ ] 🔴 **워커 종료 대기 시간 연장** — 리스너 종료 대기(기본 5초)와 docker 종료 유예(기본 10초)를
      SMTP 최악 시간(70초)보다 길게. SMTP 도중 강제 종료로 생길 수 있는 중복 발송을 없앤다.
- [ ] 🟡 **발송 중 배포 방지** — 배포 워크플로가 SENDING·EXPANDING 캠페인이 있으면 멈추거나 경고.
- [ ] 🟡 **OPS-MANUAL 3절 배포 절차 갱신** — 아직 서버 내 빌드(옛 절차)로 적혀 있다.
- [ ] 🔴 **운영자 시더의 이메일 대소문자** — `APP_PLATFORM_OPERATORS` 는 소문자로 비교하는데 가입은
      입력 그대로 저장해, 대문자가 섞인 이메일은 운영자로 지정되지 않는다.
- [ ] 🔵 **api 무중단 교체** — 배포 중 수십 초~수 분간 추적·클릭·수신거부가 502. api 2개 교대 교체.
      4GB 노드에선 메모리가 빠듯해 서버 증설 시 함께.
- [ ] 🔵 **그룹사 AWS 구성 전환 시** — Fargate ARM 용 멀티 아키텍처 이미지 빌드, Kafka(MSK) 경량화 검토.
      비용 산정은 리뷰 자료 참고.
