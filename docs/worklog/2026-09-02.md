# 작업 로그 — 2026-09-02

**구글 로그인을 실제로 켰고**(설정→버그→검증까지), 그 과정에서 돌린 보안 재검토가
**어제 한 수정 셋이 운영에서 무력했음**을 드러냈다. 전부 고치고 실증까지 마쳤다.
SES 프로덕션 액세스는 2차 거절 → 전략을 바꿔 재신청(트랜잭셔널로 범위 축소).

## 오늘 한 일 (요약)

### 1. 구글 로그인 실연동 (`03b41e9`, `8f397a8`, `04a03e1`, `627dcac`, `8f46e2f`)
V26 에 코드만 있고 한 번도 실행된 적 없던 경로를 실제로 켰다. 켜는 과정에서 세 개의
함정을 차례로 밟았고, 셋 다 "설정과 코드가 어긋나 있었다"는 같은 종류였다.

- **가입 화면만 죽어 있었다**(UX-13): 로그인은 GSI 버튼을 그리는데 가입은
  "데모에서 지원되지 않습니다" 하드코딩. 백엔드는 `/api/auth/google` 하나로
  "있으면 로그인, 없으면 즉석 가입"을 처리하므로 화면별로 다를 이유가 없었다 →
  `GoogleSignInButton` 공용 컴포넌트로 통일(로그인 쪽 중복 40여 줄도 제거).
  함께 가입 화면의 무료 한도 문구를 "월 1만 건"→"월 1,000통"으로 정정(UX-5).
- **클라이언트 ID 가 번들에 안 들어갔다**: `paths-ignore` 때문에 **빈 커밋은
  워크플로를 트리거하지 못한다**(변경 파일 0개). 설정만 바뀌었을 때 재빌드할
  수단이 없어 `workflow_dispatch` 를 추가. 이후 번들에서 클라이언트 ID 문자열을
  직접 확인해 주입을 실증.
- **첫 로그인이 401**: 실제 원인은 `PropertyValueException` — 소셜 가입자는
  비밀번호가 없는데 `UserEntity.passwordHash` 에 `@Column(nullable=false)` 가
  남아 있었다. **V26 이 스키마는 `DROP NOT NULL` 로 풀었으나 엔티티 매핑을 함께
  고치지 않은 누락.** 경로가 한 번도 실행된 적 없어 여태 숨어 있었다.
- **가입 정보 공백 보완**: 구글 가입은 회사명을 묻지 않아 워크스페이스가
  "hong 워크스페이스"로 생성된다. 입력 단계를 추가해 가입 마찰을 늘리는 대신,
  자동 이름이 그대로인 ADMIN 에게 대시보드에서 한 번 안내하고 설정으로 보낸다
  (이름 변경 기능은 이미 있었다). 발송 이력 0인 계정의 "안정적으로 발송되고
  있어요" 인사도 분기(UX-18).

### 2. 보안 재검토 — 어제 수정 셋이 운영에서 무력했다 (`c1b4d60`)
어제 닫았다고 기록한 항목들을 "정말 닫혔나"로 다시 검증했더니 셋이 작동하지 않았다.
**공통점: 코드는 맞았는데 배선(env 전달)이 빠져 무력했다.**

- **클릭 서명(SEC-5)이 실제로는 깨져 있었다** — 서명은 워커가, 검증은 api 가
  하는데 워커 env 에 키가 없어 워커는 **저장소에 공개된 개발 기본키**로 서명했다.
  즉 발송된 메일의 모든 클릭이 400. JWT 를 빌려 쓰던 것을 전용 키
  `APP_TRACKING_SIGNING_KEY` 로 분리하고 compose 가 양쪽에 같은 값을 주입 →
  배포 후 **컨테이너의 키 해시를 대조해 일치를 실증**.
- **SNS 토픽 허용목록(SEC-2)이 무효였다** — compose 가
  `APP_WEBHOOK_SNS_TOPIC_ARN` 을 컨테이너로 전달하지 않아 목록이 항상 빈 상태.
  서명만 맞으면 남의 AWS 계정 토픽도 통과했다.
- **구글 기존계정 연결이 `email_verified` 를 확인하지 않았다** — 미검증 주소로
  남의 계정을 주장하면 비밀번호 없이 워크스페이스를 탈취할 수 있었다. 진입부에서
  강제 + 빈 이메일 거부(계정 병합 방지) + 일회용 도메인 차단을 구글 경로에도 적용.
- 함께: 로그인 **계정 열거 오라클** 제거(소셜 계정 안내 문구가 "가입 여부+소셜
  여부"를 무제한 조회하게 했다 — 친절함을 포기하고 일반 실패 문구·실패 카운트로),
  소셜 전용 계정에 비밀번호 재설정 토큰 미발급(재설정만으로 비밀번호 로그인
  계정으로 전환되던 표면 제거).

### 3. 감사 잔여 3건 (`17266be`)
- **에디터 스타일·URL 주입**: `bg/color/align/pad/minH/fontSize` 가 검증 없이
  style 속성에 보간돼, API 로 심은 마커가 `"` 로 속성을 탈출해 **발송 HTML 에 임의
  태그**를 넣을 수 있었다. 값 화이트리스트(safeColor·safeAlign·safeNum)를 렌더
  직전에 강제하고, 버튼·이미지 URL 에도 스킴 검사 적용(배경에만 있던 비대칭 해소).
- **SecretsGuard 확대**: "기본값 정확 일치"만 보던 검사가 앞뒤 공백 하나로 우회됐다.
  trim + 약한 값 목록 + 최소 길이 16 으로 넓히고 **DB·RabbitMQ 비밀번호를 검사
  대상에 추가**(postgres 루프백 노출과 조합되면 서버 접근자가 전 테넌트 덤프 가능).
  배포 전 서버 값 4종이 새 기준을 통과하는지 미리 확인 — 기동 실패 위험 제거.
- **배포 권한 축소**: `workflow_dispatch` 가 임의 브랜치 배포를 허용해 리뷰를 우회한
  이미지가 `:latest` 를 덮어쓰고 그 실행에 SSH 키까지 노출됐다 → deploy 잡을
  master 로 제한, `permissions: contents: read`.

### 6. SES 프로덕션 액세스 — 2차 거절, 전략 변경
거절 사유는 비공개 정형 문구. 원인은 **"전부 새것" 프로필**로 추정: 새 AWS 계정 +
갓 등록한 도메인 + 발송 이력 0 + Mail type "Marketing"(가장 깐깐한 카테고리).
문장을 다듬는 재신청으로는 뒤집히지 않는 성격이라 접근을 바꿨다.
- 참고 사례([kth990303 블로그](https://kth990303.tistory.com/449))의 승인 요인 두 개를
  채택: **용도를 트랜잭셔널로 좁히고**, 폼 재제출이 아니라 **기존 거절 케이스에
  회신해 사람 검토를 요청**.
- 신청 범위를 "가입 인증·비밀번호 재설정만, 일 50통 미만"으로 축소(캠페인 발송은
  이력이 쌓인 뒤 별도 요청). 요청 한도도 200(샌드박스와 동일)으로 — 필요한 것은
  발송량이 아니라 **수신자 제한 해제**임을 명시.
- 대기 중. 승인되면 가입 인증 메일이 뚫려 베타 오픈이 가능해진다. 플랜 B(Postmark·
  Resend 등)는 `MailSender` 포트 구조라 SMTP 설정 교체로 갈아탈 수 있다.

## 배운 것
- **"수정했다"와 "운영에서 작동한다"는 다르다.** 오늘 무력했던 셋 다 코드는 맞았고
  배선이 빠졌다. 앞으로 보안 수정은 배포 후 **실제 동작 실증**(키 해시 대조, 오리진
  400 확인 같은)까지가 한 세트다.
- **마이그레이션은 스키마와 매핑을 함께 본다.** V26 이 `DROP NOT NULL` 을 했지만
  엔티티의 `@Column(nullable=false)` 를 남겨 실행되지 않는 경로에 버그가 잠복했다.
- **한 번도 실행되지 않은 경로는 없는 것과 같다.** 구글 로그인은 코드·마이그레이션이
  다 있었는데 클라이언트 ID 가 없어 미실행 → 켜는 순간 버그 셋이 한꺼번에 나왔다.
- 편의 기능이 보안 표면이 되는 지점: "이 계정은 Google 로 가입됐어요"라는 친절한
  안내가 곧 계정 열거 오라클이었다.
