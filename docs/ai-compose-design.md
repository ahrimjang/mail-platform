# AI 이메일 작성 설계 — 제목 후보 → 발송 전 진단 → 본문 생성

> 착수 전 설계만 정리한 문서. **베타 오픈 이후**에 손댄다(이유는 아래 "왜 지금이
> 아닌가"). 지금 정해두는 이유는 과금·게이팅·생성 스키마를 뒤늦게 정하면 되돌리기
> 비싸기 때문이다.
>
> **2026-09-18 방향 전환 — 모델은 사용자가 등록한다.** 처음 초안은 우리 API 키로 한 모델을
> 호출하는 구조였다. 이제는 워크스페이스가 자기 모델(주소·키·모델명)을 등록하고, 우리는
> **입력·출력 형식만 정해** 어떤 모델이든 연결되게 한다. 아래 "사용자 모델 연결" 절이
> 핵심이고, 과금·어댑터·보안 절을 여기에 맞춰 고쳤다. 채택 여부는 2026-09-22 리뷰에서
> 정한다([mcp-integration-design.md](mcp-integration-design.md) "리뷰에서 정할 것").

## 배경 / 문제

이메일 만들기의 실질적 진입 장벽은 **빈 화면**이다. 온보딩 체크리스트(2026-09-09)의
네 단계 중 "보낼 이메일 만들기"가 가장 오래 막히는 지점이고, 템플릿에서 시작해도
결국 문구는 사람이 다 쓴다.

다만 "AI 이메일 작성"을 범용 생성기로 붙이면 값이 안 나온다.

- 스티비·메일침프에 이미 다 있다. 같은 기능으로 후발주자가 이기는 축이 아니다
  (우리 포지셔닝은 "구독자 수가 아니라 보낸 만큼만" — **가격**이 차별 축이다).
- 범용 "뉴스레터 써줘"의 결과는 밋밋해서 사용자가 결국 전부 고친다. 고칠 거면
  빌트인 템플릿에서 시작하는 것과 차이가 작다.

이 제품이 남들보다 잘할 수 있는 건 **이미 가진 워크스페이스 데이터**다.

| 데이터 | 위치 | 쓸모 |
| --- | --- | --- |
| 실제로 이긴 제목 | `campaigns.ab_winner` + 변형별 오픈/클릭 | 제목 생성의 정답 신호 |
| 링크 클릭 랭킹 | `GET /api/campaigns/{id}/links` | 무엇이 반응을 얻었는가 |
| 과거 발송 본문 | `campaigns` 스냅샷 · `emails` | 이 브랜드의 톤 |
| 참여도 세그먼트 | `ContactEngagementService` | 누구에게 먹혔는가 |

즉 **빈 페이지에서 생성**이 아니라 **자기 성과 위에서 개선**으로 설계한다. 승자
데이터가 쌓일수록 좋아지는 루프가 돌고, 이건 남이 베끼기 어렵다.

## 왜 지금이 아닌가

- ~~SNS 바운스 웹훅이 아직 안 붙었다~~ — *2026-09-10 운영 연결·실증 완료로 해소.*
- AI 작성은 **없어서 못 쓰는 기능이 아니다.** 발송 사고와 직결되는 작은 안전장치
  ([REVIEW-product.md](REVIEW-product.md) 8절의 🔴 항목)가 먼저다.
- 승자 데이터가 아직 없다. 위 표의 강점은 **발송 이력이 쌓인 뒤에** 작동한다.
  베타 사용자가 몇 번 보내고 난 뒤가 이 기능의 제 시점이다.

## 사용자 모델 연결 (2026-09-18)

### 왜 사용자 모델인가

| 우리 키로 호출 (초안) | 사용자가 모델 등록 (현재 방향) |
| --- | --- |
| AI 비용을 우리가 낸다 → "보낸 만큼만" 과금과 충돌 | AI 비용은 **사용자의 모델 계정**으로 청구 → 충돌 없음 |
| 무료 사용자가 AI 만 쓰면 순손실 → 플랜별 횟수 한도 필요 | 횟수 한도가 필요 없다(남용 방지용 속도 제한만) |
| 모델 하나에 고정 | 사용자가 고른 모델. **그룹사 사내 모델**도 연결 가능 |
| 모델 품질이 우리 책임 | 모델 선택은 사용자 몫, 우리는 형식과 검증을 책임 |

잃는 것: 키가 없는 사용자는 AI 를 못 쓴다(가입 직후 바로 체험하는 흐름이 약해진다).
나중에 "기본 모델(우리 키, 소량 무료)"을 얹을 수는 있지만 1차 범위는 사용자 모델만.

### 연결 설정 (워크스페이스당 1개)

| 항목 | 내용 |
| --- | --- |
| 종류 | **OpenAI 호환**(1순위) · Anthropic · Gemini |
| 주소 | Base URL — OpenAI 호환이면 사내 게이트웨이·vLLM·Ollama 등도 이 칸으로 |
| 모델명 | 사용자가 입력 |
| API 키 | 암호화 저장, 화면에는 끝 4자리만. 다시 보여주지 않는다 |
| 등록 권한 | 워크스페이스 ADMIN 만 |
| 연결 확인 | 저장 전 "연결 테스트" — 짧은 요청 1회로 형식 준수까지 확인 |

**OpenAI 호환 형식을 먼저** 하는 이유: OpenAI 뿐 아니라 사내 LLM 게이트웨이와 자체 호스팅
모델 대부분이 이 형식을 쓴다. Anthropic·Gemini 는 요청·응답 형식이 달라 어댑터를 따로 둔다.

### 입력·출력 계약 — 우리가 책임지는 부분

어떤 모델이든 **같은 입력을 보내고 같은 출력을 요구**한다. 모델마다 다른 것은 어댑터가
흡수한다(요청 본문 모양, JSON 모드 지원 여부, 응답 위치).

```
입력  = 시스템 지시(역할·금지 사항) + 출력 JSON 스키마 + 컨텍스트(데이터로 구분) + 사용자 요청
출력  = 제목 후보:  { "candidates": ["...", "..."] }
        본문 생성:  { "subject": "...", "previewText": "...", "blocks": [ ...아래 블록 스키마... ] }
```

- 모델이 JSON 모드(구조화 출력)를 지원하면 켜고, 아니면 지시문 + 서버 검증으로 대신한다.
- 검증 실패 시 **1회만** 재요청하고, 그래도 실패하면 통과한 블록만으로 초안을 만든다
  (아래 "블록 생성" 절의 부분 성공 원칙).
- 응답 크기 상한과 타임아웃(60초)을 건다. 1차는 동기 호출, 스트리밍은 나중.

### MCP 와의 관계

| | 웹 내장 AI (이 문서) | MCP ([설계](mcp-integration-design.md)) |
| --- | --- | --- |
| 호출 방향 | 우리가 **모델을** 부른다 | 사내 포탈이 **우리를** 부른다 |
| 사용자가 일하는 곳 | Outpace 콘솔 | 사내 AI 포탈 |
| 발송 | 초안까지만 — 발송은 기존 콘솔 흐름 | 확정 토큰을 거쳐 포탈에서 발송 |
| 대상 | **모든 고객**(판매 기능) | 사내용 |

둘은 대체 관계가 아니다. 공통 부품(블록 스키마 검증, 본문 검증 — REVIEW-product 8절)을
먼저 만든 쪽이 다음 작업을 줄인다. 제안 순서는 **웹 내장 AI 먼저, MCP 는 포탈 요구 확인 후**.

**그룹사 환경의 제약**: 사내 모델이 내부망에만 열려 있으면 AWS 에 있는 우리 서버가 호출할
수 없다. 망 연결(VPN) 또는 사내 인프라 이전이 필요하다. 브라우저에서 모델을 직접 부르는
방식은 키가 브라우저에 노출되고 CORS 에 막혀 채택하지 않는다.

## 범위와 순서

작은 것부터, 실패해도 피해가 없는 것부터.

### 1단계 — 제목 후보 생성 (A/B 결합)
본문(또는 선택한 이메일)을 입력으로 제목 후보 3~5개. 사용자가 그중 둘을 골라
A/B 에 넣는다. **A/B 인프라가 이미 있으므로 새로 만들 게 거의 없다.**

- 토큰 비용이 본문 생성의 1/20 수준.
- 마음에 안 들면 안 쓰면 그만 — 실패 비용 0.
- 승자가 쌓이면 그 워크스페이스의 과거 승자를 few-shot 으로 넣는다 → 루프 성립.

### 2단계 — 발송 전 진단
생성이 아니라 **검사**. 평판 방어 축과 정렬되고, 2026-09-09 에 만든 등록 게이트
사전 노출(`GET /api/campaigns/preflight`)과 같은 자리에 붙는다.

- 개인화 변수 미치환(`{{name}}` 을 쓰고 연락처에 이름이 없는 비율)
- 깨진 링크 / 추적 불가 링크
- 스팸 스코어가 높은 표현, 제목의 과도한 대문자·특수문자
- 수신거부 안내 문구 누락(수신거부 **링크**는 파이프라인이 자동으로 붙지만,
  본문에 맥락 문장이 없으면 신고율이 오른다)

LLM 없이 규칙으로 되는 항목이 절반이다. 그 절반부터 만들고 나머지를 모델에 맡긴다.

### 3단계 — 본문 생성
위 둘이 자리를 잡은 다음. 아래 "블록 생성" 절이 이 단계의 핵심 제약이다.

## 설계 원칙

1. **헥사고날** — `mail-core` 에 포트, `infra` 에 어댑터. `MailSender` 포트가
   MailHog→SES 전환을 환경변수 문제로 만든 것과 같은 패턴. 모델 교체·프로바이더
   교체가 설정 문제로 남아야 한다.
2. **블록 모델로 생성한다. 통짜 HTML 금지.** (아래 절)
3. **생성 결과는 항상 초안이다.** 자동 발송으로 직행하는 경로를 만들지 않는다.
   생성 → 이메일 저장 → 기존 캠페인 흐름에 합류.
4. **AI 비용은 사용자 모델 계정으로.** 우리 쪽 횟수 한도는 두지 않는다. (아래 절)
5. **미인증 계정에는 열지 않는다.** (아래 절)

## 구성 요소

### 포트 (mail-core)

```
interface CopyGenerator {                       // 모델 프로바이더 추상화
  List<String> subjectCandidates(SubjectPrompt prompt);   // 1단계
  GeneratedEmail compose(ComposePrompt prompt);           // 3단계
}
```

프롬프트에는 **워크스페이스 컨텍스트**가 실린다 — 과거 승자 제목, 최근 발송 톤
샘플, 업종/브랜드명. 이 컨텍스트를 모으는 것은 코어의 책임이고, 모델 호출은
어댑터의 책임이다.

```
AiComposeService (mail-core)
  ├─ 게이트: 이메일 인증 → 평판 정지 → 모델 연결 등록 여부 → 워크스페이스 속도 제한
  ├─ 컨텍스트 수집: campaigns/emails/ab_winner 조회 (테넌트 격리 규칙 준수)
  ├─ CopyGenerator 호출 (워크스페이스의 연결 설정을 함께 넘김)
  └─ 사용 기록 (ai_usages — 과금용이 아니라 사용자에게 토큰 사용량을 보여주는 용도)
```

### 어댑터 (infra)

종류별 어댑터 셋 — `OpenAiCompatibleCopyGenerator`(1순위), `AnthropicCopyGenerator`,
`GeminiCopyGenerator`. 각자 요청 모양을 만들고 응답에서 JSON 을 꺼내며, 타임아웃·1회 재시도·
스키마 검증은 공통으로 둔다. 연결 설정이 없는 워크스페이스는 호출하지 않는다(로컬 무설정 동작 유지).

### 엔드포인트 (mail-api)

```
GET    /api/ai/connection                    -> { provider, baseUrl, model, keyLast4 } | 204
PUT    /api/ai/connection  { provider, baseUrl, model, apiKey? }   (ADMIN)
POST   /api/ai/connection/test                                     (ADMIN)
DELETE /api/ai/connection                                          (ADMIN)

POST /api/ai/subjects     { emailId? | subject? , body? }  -> { candidates: [...] }
POST /api/ai/diagnose     { subject, body, listId? }       -> { findings: [...] }
POST /api/ai/compose      { brief, tone?, blocks? }        -> { blocks: [...] , subject }
```

`/api/ai/**` 는 permitAll 이 **아니다**(Bearer 필수). nginx 에 `/api/auth/**` 와 같은
방식의 IP당 속도 제한을 추가한다.

### 마이그레이션

MCP 설계가 V37 을 예약했으므로 그다음 번호로 잡는다(착수 시점에 확정).

```
V38__ai_connection.sql
  ai_connections(workspace_id PK, provider, base_url, model, api_key_enc, key_last4,
                 updated_by, updated_at)
  ai_usages(id, workspace_id, kind, tokens_in, tokens_out, created_at)
```

`workspace_id` 를 갖는 루트 엔티티(테넌트 격리 원칙 V16). 키 암호화 키는
`APP_AI_KEY_ENCRYPTION_KEY` 환경변수 — 운영에서 기본값이면 기동을 거부하도록 `SecretsGuard` 에 추가.

## 블록 생성 — 이 설계에서 제일 중요한 제약

LLM 이 **통짜 HTML** 을 뱉게 하면 결과가 HTML 에디터로만 열린다. 블록 마커
(`<!--opblocks:...-->`)가 없어서 블록 에디터가 구조를 복원하지 못하기 때문이다.
그러면 사용자는 "한 번 뽑고 손댈 수 없는 결과"를 받는다 — 쓸모 있는 AI 와 없는 AI 를
가르는 지점이 여기다.

그래서 모델은 `frontend/src/outpace/blocks.ts` 의 **블록 배열(JSON)** 을 생성한다.

```jsonc
[
  { "type": "text",   "heading": "3월 소식", "body": "안녕하세요 {{name}}님, ...", "align": "left", "bg": "#ffffff" },
  { "type": "button", "label": "자세히 보기", "url": "https://…", "align": "center", "bg": "#ffffff" },
  { "type": "footer", "text": "수신을 원치 않으시면…", "bg": "#f4f4f5" }
]
```

제약:

- 허용 타입은 `text | image | button | two | divider | footer` 뿐. 그 외는 거부.
- `id` 는 모델이 만들지 않는다 — 서버가 `newBlock()` 규칙으로 채운다.
- 리치 필드(`body`/`leftBody`/`rightBody`/`text`)는 `sanitizeRich` 화이트리스트
  (b/i/a/br)를 통과시킨다. **모델 출력은 신뢰하지 않는 입력으로 취급한다** —
  2026-09-02 에 닫은 에디터 스타일 주입(SEC)과 같은 이유다.
- 스타일 필드(`bg`/`color`/`align`/`padY`/`padX`)는 `safeColor`/`safeAlign`/`safeNum`
  를 통과해야 한다. 통과 못 하면 필드를 버리고 기본값을 쓴다(생성 전체를 버리지 않음).
- `image.url` 은 모델이 채우지 않는다. 빈 문자열로 두면 캔버스가 플레이스홀더를
  그리고 사용자가 업로드한다. **모델이 만든 외부 이미지 URL 을 발송 메일에 싣지 않는다.**
- 개인화 변수는 `{{name}}` 등 알려진 토큰만 허용. 모르는 토큰은 평문으로 강등.

검증에 실패한 블록은 버리고 나머지로 이메일을 만든다. 부분 성공이 전체 실패보다 낫다.

AI 비용은 사용자의 모델 계정에 청구되므로 플랜별 횟수 한도 표는 폐기한다.

남는 것:

- **남용 방지용 속도 제한** — 워크스페이스당 분당 요청 수 상한(서버 보호용, 과금 아님).
- **플랜 게이팅 여부는 리뷰에서 결정** — 비용이 사용자 몫이라 전 플랜 개방이 자연스럽지만,
  유료 전환 동기로 STANDARD 이상에만 여는 선택지도 있다.
- 화면에 **이번 달 토큰 사용량**을 보여준다(사용자가 자기 모델 비용을 가늠하도록).
  단가는 모델마다 달라 금액 환산은 하지 않는다.

## 어뷰즈 / 보안

AI 작성은 **콘텐츠 대량 생산**을 쉽게 만들어 스팸 발송자에게 매력적인 조합이 된다.
지금 평판 가드는 "명단 품질"을 보지만 콘텐츠 생산 속도는 보지 않는다.

- **미인증 계정에는 열지 않는다** (`assertCurrentUserVerified` — 캠페인 등록과 동일).
- 평판 정지 워크스페이스도 차단.
- 워밍업 게이트가 대량 발사를 막으므로, 어뷰저는 계정을 여러 개 만드는 쪽으로 간다
  → 베타 정원(`APP_BETA_SIGNUP_CAP`)과 일회용 도메인 차단이 1차 방어로 유지된다.
- **프롬프트 인젝션**: 컨텍스트에 과거 발송 본문을 넣으므로, 본문에 심긴 지시문이
  모델을 조종할 수 있다. 컨텍스트는 명시적으로 "데이터"로 구분해 전달하고, 출력은
  위 스키마 검증을 통과해야만 쓴다(자연어 지시를 실행하는 경로 자체가 없다).
- 모델 프로바이더로 나가는 데이터에 **수신자 개인정보를 넣지 않는다** — 컨텍스트는
  제목·본문·집계 지표까지. 연락처 이메일·이름은 보내지 않는다. 개인정보처리방침
  갱신 필요 여부를 착수 시 확인할 것. 사용자 모델 방식에서는 **보낼 곳을 고객이 지정**하므로
  "고객 지시에 따라 고객이 정한 모델로 전송한다"는 문구로 정리한다.

사용자 모델 연결이 새로 만드는 위험:

- **SSRF** — 사용자가 주소를 입력하므로 우리 서버가 내부망을 부르는 통로가 될 수 있다.
  https 만 허용, DNS 해석 후 사설·루프백·링크로컬 대역(클라우드 메타데이터 `169.254.169.254`
  포함) 거부, 리다이렉트 따라가지 않음, 응답 크기 상한. 그룹사가 사내망 모델을 붙일 때는
  플랫폼 운영자가 허용 호스트(`APP_AI_ALLOWED_HOSTS`)를 지정해 예외를 연다.
- **키 유출** — 암호화 저장, 로그·오류 메시지·API 응답에 키를 싣지 않는다, 끝 4자리만 표시.
  키 변경은 감사 기록(누가·언제)을 남긴다.
- **키를 남의 워크스페이스가 쓰는 일** — 연결 설정은 워크스페이스 루트 엔티티라 테넌트 격리
  규칙(by-id 404)을 그대로 따른다.

## 단계별 체크리스트

### 0단계 — 모델 연결
- [ ] V38 마이그레이션(`ai_connections`, `ai_usages`) + 키 암호화(`APP_AI_KEY_ENCRYPTION_KEY`, SecretsGuard)
- [ ] OpenAI 호환 어댑터 + SSRF 방어(대역 거부·https·리다이렉트 금지·크기 상한·허용 호스트 예외)
- [ ] 연결 설정 화면(관리 페이지) + 연결 테스트
- [ ] Anthropic·Gemini 어댑터는 요청이 있을 때

### 1단계 — 제목 후보
- [ ] `CopyGenerator` 포트 — 연결 설정을 인자로 받는다
- [ ] `AiComposeService.subjectCandidates` — 게이트·컨텍스트 수집·사용량 기록
- [ ] `POST /api/ai/subjects` + nginx 속도 제한
- [ ] 작성 화면: 제목 옆 "후보 받기" → 고른 둘을 A/B 에 넣기
- [ ] 모델 미연결이면 버튼 대신 "모델 연결하기" 안내

### 2단계 — 발송 전 진단
- [ ] 규칙 기반 검사부터(변수 미치환·깨진 링크·수신거부 문구)
- [ ] 확인 모달에 결과 표시 — 경고는 막지 않고 알린다(오탐 비용이 크다)

### 3단계 — 본문 생성
- [ ] 블록 스키마 검증기(`sanitizeRich`/`safeColor` 재사용)
- [ ] `POST /api/ai/compose` → 이메일로 저장 → 에디터로 이동
- [ ] 생성 결과에 "AI 초안" 표시는 **콘솔 안에서만** — 발송 메일에는 남기지 않는다

## 미결 질문

- ~~모델 프로바이더와 단가, 월 예상 비용의 손익 검증~~ — 사용자 모델 방식으로 불필요.
- 한국어 카피 품질이 실제로 쓸 만한지 — 모델마다 다르므로, 착수 전 대표 모델 2~3개로
  같은 프롬프트 20건씩 뽑아 **출력 형식 준수율**과 품질을 함께 본다. 형식 준수율이 낮은
  모델은 연결 테스트에서 경고한다.
- 플랜 게이팅: 전 플랜 개방 vs STANDARD 이상 — 리뷰 결정 항목.
- 키가 없는 사용자를 위한 "기본 모델(우리 키, 소량 무료)"을 둘지 — 1차 범위 밖.
- 진단의 스팸 스코어를 자체 규칙으로 할지 외부 도구(SpamAssassin 등)를 붙일지.
