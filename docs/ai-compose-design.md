# AI 이메일 작성 설계 — 제목 후보 → 발송 전 진단 → 본문 생성

> 착수 전 설계만 정리한 문서. **베타 오픈 이후**에 손댄다(이유는 아래 "왜 지금이
> 아닌가"). 지금 정해두는 이유는 과금·게이팅·생성 스키마를 뒤늦게 정하면 되돌리기
> 비싸기 때문이다.

## 배경 / 문제

이메일 만들기의 실질적 진입 장벽은 **빈 화면**이다. 온보딩 체크리스트(2026-09-09)의
네 단계 중 "보낼 이메일 만들기"가 가장 오래 막히는 지점이고, 템플릿에서 시작해도
결국 문구는 사람이 다 쓴다.

다만 "AI 이메일 작성"을 범용 생성기로 붙이면 값이 안 나온다.

- 스티비·메일침프에 이미 다 있다. 같은 기능으로 후발주자가 이기는 축이 아니다
  (우리 포지셔닝은 "구독자 수가 아니라 보낸 만큼만" — **가격**이 차별 축이다).
- 범용 "뉴스레터 써줘"의 결과는 밋밋해서 사용자가 결국 전부 고친다. 고칠 거면
  빌트인 템플릿에서 시작하는 것과 차이가 작다.

이 제품이 남들보다 잘할 수 있는 건 **이미 가진 워크스페이스 데이터**다.

| 데이터 | 위치 | 쓸모 |
| --- | --- | --- |
| 실제로 이긴 제목 | `campaigns.ab_winner` + 변형별 오픈/클릭 | 제목 생성의 정답 신호 |
| 링크 클릭 랭킹 | `GET /api/campaigns/{id}/links` | 무엇이 반응을 얻었는가 |
| 과거 발송 본문 | `campaigns` 스냅샷 · `emails` | 이 브랜드의 톤 |
| 참여도 세그먼트 | `ContactEngagementService` | 누구에게 먹혔는가 |

즉 **빈 페이지에서 생성**이 아니라 **자기 성과 위에서 개선**으로 설계한다. 승자
데이터가 쌓일수록 좋아지는 루프가 돌고, 이건 남이 베끼기 어렵다.

## 왜 지금이 아닌가

- **SNS 바운스 웹훅이 아직 안 붙었다.** 평판 가드 4단 중 억제·자동정지가 입력을
  못 받는 상태다. 이 상태로 베타를 열면 SES 공유 IP 평판이 사고 한 번에 무너진다.
- AI 작성은 **없어서 못 쓰는 기능이 아니다.** 웹훅은 없으면 사고가 난다.
- 승자 데이터가 아직 없다. 위 표의 강점은 **발송 이력이 쌓인 뒤에** 작동한다.
  베타 사용자가 몇 번 보내고 난 뒤가 이 기능의 제 시점이다.

## 범위와 순서

작은 것부터, 실패해도 피해가 없는 것부터.

### 1단계 — 제목 후보 생성 (A/B 결합)
본문(또는 선택한 이메일)을 입력으로 제목 후보 3~5개. 사용자가 그중 둘을 골라
A/B 에 넣는다. **A/B 인프라가 이미 있으므로 새로 만들 게 거의 없다.**

- 토큰 비용이 본문 생성의 1/20 수준.
- 마음에 안 들면 안 쓰면 그만 — 실패 비용 0.
- 승자가 쌓이면 그 워크스페이스의 과거 승자를 few-shot 으로 넣는다 → 루프 성립.

### 2단계 — 발송 전 진단
생성이 아니라 **검사**. 평판 방어 축과 정렬되고, 2026-09-09 에 만든 등록 게이트
사전 노출(`GET /api/campaigns/preflight`)과 같은 자리에 붙는다.

- 개인화 변수 미치환(`{{name}}` 을 쓰고 연락처에 이름이 없는 비율)
- 깨진 링크 / 추적 불가 링크
- 스팸 스코어가 높은 표현, 제목의 과도한 대문자·특수문자
- 수신거부 안내 문구 누락(수신거부 **링크**는 파이프라인이 자동으로 붙지만,
  본문에 맥락 문장이 없으면 신고율이 오른다)

LLM 없이 규칙으로 되는 항목이 절반이다. 그 절반부터 만들고 나머지를 모델에 맡긴다.

### 3단계 — 본문 생성
위 둘이 자리를 잡은 다음. 아래 "블록 생성" 절이 이 단계의 핵심 제약이다.

## 설계 원칙

1. **헥사고날** — `mail-core` 에 포트, `infra` 에 어댑터. `MailSender` 포트가
   MailHog→SES 전환을 환경변수 문제로 만든 것과 같은 패턴. 모델 교체·프로바이더
   교체가 설정 문제로 남아야 한다.
2. **블록 모델로 생성한다. 통짜 HTML 금지.** (아래 절)
3. **생성 결과는 항상 초안이다.** 자동 발송으로 직행하는 경로를 만들지 않는다.
   생성 → 이메일 저장 → 기존 캠페인 흐름에 합류.
4. **발송량 과금과 분리된 쿼터.** (아래 절)
5. **미인증 계정에는 열지 않는다.** (아래 절)

## 구성 요소

### 포트 (mail-core)

```
interface CopyGenerator {                       // 모델 프로바이더 추상화
  List<String> subjectCandidates(SubjectPrompt prompt);   // 1단계
  GeneratedEmail compose(ComposePrompt prompt);           // 3단계
}
```

프롬프트에는 **워크스페이스 컨텍스트**가 실린다 — 과거 승자 제목, 최근 발송 톤
샘플, 업종/브랜드명. 이 컨텍스트를 모으는 것은 코어의 책임이고, 모델 호출은
어댑터의 책임이다.

```
AiComposeService (mail-core)
  ├─ 게이트: 이메일 인증 → 평판 정지 → 플랜 → AI 쿼터
  ├─ 컨텍스트 수집: campaigns/emails/ab_winner 조회 (테넌트 격리 규칙 준수)
  ├─ CopyGenerator 호출
  └─ 사용량 기록 (ai_usages)
```

### 어댑터 (infra)

`AnthropicCopyGenerator` — API 호출, 타임아웃, 재시도, 응답 스키마 검증.
개발 기본값은 **호출하지 않는 스텁**(`app.ai.enabled:false`)이라 로컬은 무설정
동작 원칙을 유지한다.

### 엔드포인트 (mail-api)

```
POST /api/ai/subjects     { emailId? | subject? , body? }  -> { candidates: [...] }
POST /api/ai/diagnose     { subject, body, listId? }       -> { findings: [...] }
POST /api/ai/compose      { brief, tone?, blocks? }        -> { blocks: [...] , subject }
```

`/api/ai/**` 는 permitAll 이 **아니다**(Bearer 필수). nginx 에 `/api/auth/**` 와 같은
방식의 IP당 속도 제한을 추가한다.

### 마이그레이션

```
V34__ai_usage.sql
  ai_usages(id, workspace_id, kind, tokens_in, tokens_out, created_at)
  workspaces.ai_monthly_cap  (null = 플랜 기본값)
```

`workspace_id` 를 갖는 루트 엔티티(테넌트 격리 원칙 V16). 월 사용량은
`PlanLimits.monthlySent` 와 같은 방식으로 집계한다.

## 블록 생성 — 이 설계에서 제일 중요한 제약

LLM 이 **통짜 HTML** 을 뱉게 하면 결과가 HTML 에디터로만 열린다. 블록 마커
(`<!--opblocks:...-->`)가 없어서 블록 에디터가 구조를 복원하지 못하기 때문이다.
그러면 사용자는 "한 번 뽑고 손댈 수 없는 결과"를 받는다 — 쓸모 있는 AI 와 없는 AI 를
가르는 지점이 여기다.

그래서 모델은 `frontend/src/outpace/blocks.ts` 의 **블록 배열(JSON)** 을 생성한다.

```jsonc
[
  { "type": "text",   "heading": "3월 소식", "body": "안녕하세요 {{name}}님, ...", "align": "left", "bg": "#ffffff" },
  { "type": "button", "label": "자세히 보기", "url": "https://…", "align": "center", "bg": "#ffffff" },
  { "type": "footer", "text": "수신을 원치 않으시면…", "bg": "#f4f4f5" }
]
```

제약:

- 허용 타입은 `text | image | button | two | divider | footer` 뿐. 그 외는 거부.
- `id` 는 모델이 만들지 않는다 — 서버가 `newBlock()` 규칙으로 채운다.
- 리치 필드(`body`/`leftBody`/`rightBody`/`text`)는 `sanitizeRich` 화이트리스트
  (b/i/a/br)를 통과시킨다. **모델 출력은 신뢰하지 않는 입력으로 취급한다** —
  2026-09-02 에 닫은 에디터 스타일 주입(SEC)과 같은 이유다.
- 스타일 필드(`bg`/`color`/`align`/`padY`/`padX`)는 `safeColor`/`safeAlign`/`safeNum`
  를 통과해야 한다. 통과 못 하면 필드를 버리고 기본값을 쓴다(생성 전체를 버리지 않음).
- `image.url` 은 모델이 채우지 않는다. 빈 문자열로 두면 캔버스가 플레이스홀더를
  그리고 사용자가 업로드한다. **모델이 만든 외부 이미지 URL 을 발송 메일에 싣지 않는다.**
- 개인화 변수는 `{{name}}` 등 알려진 토큰만 허용. 모르는 토큰은 평문으로 강등.

검증에 실패한 블록은 버리고 나머지로 이메일을 만든다. 부분 성공이 전체 실패보다 낫다.

## 과금·게이팅

**발송량 과금과 충돌한다.** "보낸 만큼만"인데 AI 는 발송과 무관하게 비용이 난다.
무료 스타터(월 1,000통) 사용자가 AI 만 쓰고 발송을 안 하면 순손실이다.

정책(초안 — [BILLING-policy.md](BILLING-policy.md) 에 반영 필요):

| 플랜 | 제목 후보 | 발송 전 진단 | 본문 생성 |
| --- | --- | --- | --- |
| STARTER | 월 20회 | 무제한(규칙 기반) | ✕ |
| STANDARD | 월 200회 | 무제한 | 월 20회 |
| PRO 이상 | 무제한(공정사용) | 무제한 | 월 200회 |

- 한도 초과는 `PlanLimitExceededException`(409) — 기존 한도와 같은 창구.
- **집행 지점은 요청 시점.** 발송 중 컷오프 금지 원칙과 무관한 영역이다.
- `GET /api/campaigns/preflight` 처럼 **남은 횟수를 화면에 미리 보여준다.**
  마지막 클릭에서 처음 알게 하지 않는다(2026-09-09 교훈).

## 어뷰즈 / 보안

AI 작성은 **콘텐츠 대량 생산**을 쉽게 만들어 스팸 발송자에게 매력적인 조합이 된다.
지금 평판 가드는 "명단 품질"을 보지만 콘텐츠 생산 속도는 보지 않는다.

- **미인증 계정에는 열지 않는다** (`assertCurrentUserVerified` — 캠페인 등록과 동일).
- 평판 정지 워크스페이스도 차단.
- 워밍업 게이트가 대량 발사를 막으므로, 어뷰저는 계정을 여러 개 만드는 쪽으로 간다
  → 베타 정원(`APP_BETA_SIGNUP_CAP`)과 일회용 도메인 차단이 1차 방어로 유지된다.
- **프롬프트 인젝션**: 컨텍스트에 과거 발송 본문을 넣으므로, 본문에 심긴 지시문이
  모델을 조종할 수 있다. 컨텍스트는 명시적으로 "데이터"로 구분해 전달하고, 출력은
  위 스키마 검증을 통과해야만 쓴다(자연어 지시를 실행하는 경로 자체가 없다).
- 모델 프로바이더로 나가는 데이터에 **수신자 개인정보를 넣지 않는다** — 컨텍스트는
  제목·본문·집계 지표까지. 연락처 이메일·이름은 보내지 않는다. 개인정보처리방침
  갱신 필요 여부를 착수 시 확인할 것.

## 단계별 체크리스트

### 1단계 — 제목 후보
- [ ] `CopyGenerator` 포트 + 스텁 어댑터, `app.ai.enabled` 토글
- [ ] `AiComposeService.subjectCandidates` — 게이트·컨텍스트 수집·쿼터 기록
- [ ] V34 마이그레이션(`ai_usages`, `workspaces.ai_monthly_cap`)
- [ ] `POST /api/ai/subjects` + nginx 속도 제한
- [ ] 작성 화면: 제목 옆 "후보 받기" → 고른 둘을 A/B 에 넣기
- [ ] 남은 횟수 사전 노출(preflight 확장 또는 응답 헤더)

### 2단계 — 발송 전 진단
- [ ] 규칙 기반 검사부터(변수 미치환·깨진 링크·수신거부 문구)
- [ ] 확인 모달에 결과 표시 — 경고는 막지 않고 알린다(오탐 비용이 크다)

### 3단계 — 본문 생성
- [ ] 블록 스키마 검증기(`sanitizeRich`/`safeColor` 재사용)
- [ ] `POST /api/ai/compose` → 이메일로 저장 → 에디터로 이동
- [ ] 생성 결과에 "AI 초안" 표시는 **콘솔 안에서만** — 발송 메일에는 남기지 않는다

## 미결 질문

- 모델 프로바이더와 단가, 월 예상 비용(플랜별 한도 × 예상 사용률)의 손익 검증.
- 한국어 카피 품질이 실제로 쓸 만한지 — 착수 전 수동 프롬프트로 20건 정도
  뽑아보고 판단한다. 여기서 안 나오면 1단계도 접는다.
- 진단의 스팸 스코어를 자체 규칙으로 할지 외부 도구(SpamAssassin 등)를 붙일지.
